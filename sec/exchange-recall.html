Exchange Online Message Recall

Microsoft 365 pozwoli odwoływać wiadomości między organizacjami

Microsoft rozszerza funkcję Message Recall w Exchange Online. Administratorzy będą mogli wskazać zaufane tenanty Microsoft 365, z których użytkownicy mogą odwoływać wiadomości wysłane do organizacji odbierającej.

Co się zmienia

Message Recall przestaje być funkcją ograniczoną wyłącznie do jednej organizacji.

Problem

Recall działał tylko w jednym tenancie

Do tej pory odwołanie wiadomości działało tylko wtedy, gdy nadawca i odbiorca należeli do tego samego tenanta Microsoft 365.

brak obsługi partnerów biznesowych
problem dla grup kapitałowych
oddzielne tenanty nie mogły korzystać z Recall

Nawet blisko współpracujące organizacje nie mogły wzajemnie odwoływać błędnie wysłanych wiadomości.

Zmiana

Cross-Tenant Message Recall

Microsoft dodaje możliwość odwoływania wiadomości pomiędzy różnymi tenantami Microsoft 365.

obsługa wielu organizacji
lista zaufanych tenantów
znany mechanizm Recall

Funkcja rozszerza istniejący proces Recall, ale nadal działa w kontrolowany sposób.

Kontrola

Decyzja należy do odbiorcy

To organizacja odbierająca wiadomość decyduje, czy zewnętrzny tenant może odwoływać wiadomości ze skrzynek jej użytkowników.

funkcja domyślnie wyłączona
wymaga jawnej konfiguracji
działa tylko dla tenantów z allow listy

Organizacja zachowuje kontrolę nad tym, kto może wykonać Recall wobec jej użytkowników.

Jak działa Cross-Tenant Message Recall

Mechanizm opiera się na zaufaniu skonfigurowanym po stronie organizacji odbierającej wiadomości.

Tenant odbierający

Administrator wskazuje komu ufa

włącza funkcję Cross-Tenant Recall
dodaje identyfikatory zaufanych tenantów
zarządza listą organizacji zewnętrznych

Bez dodania tenanta do listy zaufanych organizacji odwołanie wiadomości z zewnątrz nie zostanie wykonane.

Tenant wysyłający

Użytkownik uruchamia Recall

Exchange Online sprawdza allow listę
tenant nadawcy jest weryfikowany
Recall zostaje zaakceptowany albo odrzucony

Jeżeli tenant nadawcy nie jest dozwolony, nadawca zobaczy informację, że wiadomości nie można odwołać między organizacjami.

Przykład działania

Najprościej wyobrazić to sobie na przykładzie dwóch firm pracujących w oddzielnych tenantach Microsoft 365.

Krok 1

Contoso dodaje Fabrikam

Administrator Contoso dodaje tenant Fabrikam do listy zaufanych organizacji dla Cross-Tenant Message Recall.

Krok 2

Fabrikam odwołuje wiadomość

Użytkownik Fabrikam wysyła wiadomość do Contoso, a następnie uruchamia Message Recall.

Krok 3

Exchange Online sprawdza zaufanie

Jeżeli Fabrikam znajduje się na allow liście Contoso, odwołanie wiadomości zostaje wykonane jak standardowy Recall.

Konfiguracja przez Exchange Online PowerShell

Funkcję konfiguruje administrator Exchange Online.

Włączenie funkcji

CrossTenantRecallEnabled

Aby włączyć możliwość obsługi Recall między tenantami, administrator ustawia parametr na wartość true.

Set-CrossTenantRecallConfiguration -CrossTenantRecallEnabled $true

Wyłączenie funkcji

Domyślnie wyłączone

Funkcja jest domyślnie wyłączona. Można ją również wyłączyć ręcznie.

Set-CrossTenantRecallConfiguration -CrossTenantRecallEnabled $false

Dodanie tenantów

AllowedSenderTenantIds

Do listy dodaje się identyfikatory tenantów organizacji, którym ufamy.

Set-CrossTenantRecallConfiguration -AllowedSenderTenantIds @{Add="<tenantId>"}

Usunięcie tenantów

Zmiana listy zaufania

Tenant można usunąć z listy, jeżeli organizacja nie powinna już mieć możliwości odwoływania wiadomości.

Set-CrossTenantRecallConfiguration -AllowedSenderTenantIds @{Remove="<tenantId>"}

Co zobaczą użytkownicy

Z perspektywy użytkownika funkcja zachowuje się podobnie do klasycznego Message Recall.

Nadawca

Raport Recall

Nadawca otrzyma informację, czy odwołanie wiadomości zostało wykonane, czy zostało zablokowane z powodu braku zaufania między tenantami.

Odbiorca

Powiadomienia

Jeżeli organizacja ma włączone powiadomienia Recall dla odbiorców, będą one stosowane również dla odwołań między tenantami.

Brak zaufania

Recall się nie wykona

Jeżeli tenant nadawcy nie znajduje się na allow liście organizacji odbierającej, odwołanie wiadomości nie zostanie zrealizowane.

Co powinien zrobić administrator

Przed włączeniem funkcji warto świadomie ustalić, które organizacje powinny znaleźć się na liście zaufanych tenantów.

Zweryfikuj relacje organizacyjne

Sprawdź, z którymi firmami, spółkami lub partnerami organizacja faktycznie współpracuje na tyle blisko, aby dopuścić Recall między tenantami.

Ustal zasady zaufania

Allow lista powinna być świadomą decyzją administracyjną, a nie automatycznym rozszerzeniem dla wszystkich zewnętrznych organizacji.

Udokumentuj tenant ID

Przygotuj i zweryfikuj identyfikatory tenantów organizacji, które mają zostać dodane do konfiguracji.

Poinformuj helpdesk

Zespół wsparcia powinien wiedzieć, że Recall może działać również między organizacjami, ale wyłącznie dla tenantów z allow listy.

Dlaczego to jest ważne

W wielu firmach współpraca nie kończy się na jednym tenancie Microsoft 365.

Grupy kapitałowe, spółki zależne, partnerzy biznesowi i organizacje połączone procesami często pracują na osobnych środowiskach Microsoft 365.

Cross-Tenant Message Recall pozwala ograniczyć skutki błędnie wysłanych wiadomości również w takich scenariuszach, ale bez oddawania kontroli nad skrzynkami użytkowników zewnętrznym organizacjom.

TL;DR

Message Recall może działać między tenantami

Microsoft wprowadza Cross-Tenant Message Recall w Exchange Online.

– funkcja jest domyślnie wyłączona
– wymaga allow listy po stronie odbiorcy
– dotyczy zaufanych tenantów Microsoft 365

To praktyczna zmiana dla organizacji, które współpracują poza granicą jednego tenanta.

Co to oznacza dla firmy

Firmy z wieloma tenantami lub stałymi partnerami biznesowymi zyskują większą elastyczność w zarządzaniu błędnie wysłaną pocztą.

– mniej ograniczeń przy współpracy z partnerami
– większa kontrola po stronie administratora
– bezpieczniejszy model oparty o jawne zaufanie

To nie jest automatyczne otwarcie skrzynek dla zewnętrznych organizacji. To kontrolowana funkcja zarządzana przez administratora.

To jedna z bardziej praktycznych zmian dla administratorów Exchange Online.

Szczególnie istotne dla grup kapitałowych, partnerów i firm pracujących w wielu środowiskach Microsoft 365.
