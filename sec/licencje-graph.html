Masowe przypisywanie licencji Microsoft 365 bez grup

Jeśli masz przypisania licencji per-user i nie możesz przejść od razu na Entra ID Security Groups – jedynym sensownym rozwiązaniem jest Microsoft Graph API, czyli masowe operacje przypisywania licencji wykonywane przez PowerShell.

TL;DR
Microsoft Grapph
GUID vs SkuId
Usage Location
Licencjonowanie

Dlaczego nie ma jednego źródła prawdy o licencjach

Problem nie wynika z narzędzia – tylko z modelu licencjonowania w Entra.

Problem

Mieszane przypisanie

Możesz jednocześnie przypisać licencję per-user i przez grupę – i nie zużyjesz jej podwójnie.

Możesz też:
– dodać przypisanie grupowe do użytkownika, który już ma licencję bezpośrednio
– usunąć przypisanie per-user, jeśli licencja nadal jest przypisana przez grupę i per-user

Problem polega na tym, że mieszanie obu metod wprowadza brak kontroli i utrudnia zarządzanie – nie masz jednego źródła prawdy o licencjach.



Dodatki
Add-on przypisany przez grupę działa tylko wtedy, gdy licencja bazowa jest przypisana w tej samej grupie.
Ten sam zestaw użytkowników w innej grupie nie wystarczy.
Problem

Nieaktualne dane Microsoft

Dokumentacja Microsoft nie zawiera nowych SKU – dokumentacja licencji

Aktualizacja: 03.2025 • Stan aktualny: 07.2026

MICROSOFT_365_COPILOT_FOR_BUSINESS nie istnieje w tym pliku, mimo że działa w Graph.

Problem

Niespójne identyfikatory licencji

Ta sama licencja ma różne identyfikatory w zależności od narzędzia:

Portal: Product name
PowerShell v1: String ID
Microsoft Graph: SkuPartNumber + SkuId (GUID)

Efekt: nie masz pewności, czy operujesz na tej samej licencji.

SkuId (GUID) to jedyny identyfikator, którego używasz do przypisania licencji przez Microsoft Graph.

Wniosek

Jedyną stabilną metodą masowego przypisywania licencji jest używanie SkuId w Microsoft Graph API. To ten identyfikator faktycznie przypisuje licencję.

Schemat działania

Zamiast skakać między komendami – trzymaj się jednego flow.

1

Pobierz listę SKU

Get-MgSubscribedSku

2

Przygotuj CSV

Lista UserPrincipalName – jedna kolumna

3

Sprawdź Usage Location

Bez tego licencja się nie przypisze

4

Przypisz licencję

Set-MgUserLicense

5

Zweryfikuj przypisanie

assignedLicenses/any(x:x/skuId eq ...)

Najważniejsze komendy

Minimum potrzebne do działania – operacje w Microsoft Graph.

Przypisanie licencji

Import-Csv "C:\temp\users.csv" | % { Set-MgUserLicense -UserId $_.UserPrincipalName -AddLicenses @{SkuId="GUID"} -RemoveLicenses @() }

Usunięcie licencji

Import-Csv "C:\temp\users.csv" | % { Set-MgUserLicense -UserId $_.UserPrincipalName -AddLicenses @() -RemoveLicenses @("GUID") }

Ustawienie Usage Location

Update-MgUser -UserId user@domain.com -UsageLocation "PL"

Sprawdzenie przypisania

Get-MgUser -All -Filter "assignedLicenses/any(x:x/skuId eq GUID)"

Błąd

Brak Usage Location

Skrypt zatrzyma się na pierwszym użytkowniku bez lokalizacji.

Błąd

Pusty UPN

CSV może zawierać puste lub błędne rekordy.

Błąd

Zły GUID

SkuId musi pochodzić z tenantu – nie z dokumentacji Microsoft.

TL;DR

Graph zamiast klików

Przy dużej liczbie użytkowników GUI przestaje działać.

Graph daje pełną kontrolę nad:

– bulk operacjami
– kontrolą SKU
– powtarzalnością

Co to oznacza dla admina

Jeśli robisz migrację lub cleanup licencji – Graph nie jest opcją. To jedyne narzędzie, które działa przewidywalnie na dużą skalę.

SKU ID, których nie ma w pliku Microsoft

Oficjalny plik Microsoft Product names and service plan identifiers for licensing jest bardzo przydatny jako punkt odniesienia, ale nie powinien być traktowany jako jedyne źródło prawdy przy automatyzacji przypisywania licencji.
